# NodeSharpRead

Node-RED(https://nodered.org/) 의 기능을 C#(.NET)으로 재구현하는 프로젝트.
개발 베이스 참조 라이브러리: [lssLib](https://github.com/sslee0411/lssLib.git)

## 프로젝트 목표

Node-RED의 플로우 기반(Flow-based) 시각적 프로그래밍 방식을 C# 환경에서 재현한다.

## 진행 단계

1. 기존 Node-RED 구조 분석, 정리, 시각화
2. 기존 Node-RED 기능 분석, 정리, 시각화
3. 새로운 C# 프로그램의 구조 설계
4. 새로운 C# 프로그램 구현

## 개발 지침 (프로젝트 전 기간 준수)

1. **디버깅·모니터링 화면 가독성** — 실행 중 디버깅/모니터링 화면은 사용자가 한눈에 보기 좋고, 분석하기 쉬워야 한다.
2. **상세 주석 + 상세 예제** — 코드가 길어지더라도 주석은 상세하게 작성하고, 사용 예제도 상세하게 설명한다 (D:\lssLib 기존 코드 컨벤션 승계).
3. **구현 목록 세분화 + 초보자 설명** — 구현 목록은 세부 단위로 나누고, 각 항목이 무슨 내용인지 초보자도 알기 쉽게 자세히 설명한다.
4. **설정 화면 가독성 + 파라미터 설명 상세화** — 설정/디버깅/모니터링 화면은 사용자가 쉽게 보고 확인할 수 있어야 하고, 문제 발생 시 원인 분석이 쉬워야 한다. 파라미터 설정 항목은 설명(도움말)을 자세히 기재해 알기 쉽게 한다.
5. **단계별 시스템/연동 공백 점검** — 코드를 신규 작성하거나 기존 코드를 수정할 때는 한 번에 끝내지 않고, 아래 단계를 순서대로 체크한다. 각 단계는 이전 단계가 끝난 뒤 진행하며, 발견한 공백은 "왜 지금까지 없었는지"까지 근거를 남긴다.
   1. **변경 범위 확정** — 이번에 추가/수정하는 기능이 어떤 파일·클래스·이벤트에 영향을 주는지 먼저 나열한다.
   2. **시스템 공백 점검** — 부팅/로딩 순서, 크래시·재기동 시 상태 복구, 리소스(디스크/메모리/스레드) 감시, 보안(권한·암호화·로테이션), 배포/운영 환경(전원·업데이트·방화벽) 관점에서 이번 변경이 새로운 공백을 만들지 않는지 확인한다.
   3. **연동 공백 점검** — 이번에 손댄 기능이 다른 화면·다른 프로세스(Editor/Runner)·외부 시스템(MES/ERP, Dashboard 등)과 데이터가 오가는 지점이 있다면, 그 연결의 UI/데이터 양쪽이 모두 설계돼 있는지 확인한다(데이터만 있고 화면 전환은 없는 식의 반쪽 설계를 피한다).
   4. **자체 정합성 재검증** — grep 등으로 방금 도입한 타입/이벤트/카드 번호가 문서·코드 전체에서 일관되게 참조되는지 재확인한다(교차 참조 오기, 중복 정의, 번호 밀림 등).
   5. **기록** — 위 점검에서 실제로 발견한 것만 문서/커밋 로그에 남긴다(발견한 게 없으면 "점검했으나 해당 없음"으로 짧게 기록 — 점검 자체를 생략하지 않는다).

## 설계 방향 (확정)

- 에디터 UI: **WPF 데스크톱 앱** (브라우저 캔버스 아님)
- 참조 패턴: lssLib 기반 iiot-system-arch의 Contracts/Runtime/Registry/Editor(WPF)/Plugins 구조
- Function 노드: **듀얼 모드** — NCalc 표현식(경량, 코드 불필요) + Roslyn Scripting(C# 코드, 컴파일 캐시), `IFunctionExecutor` 전략 패턴으로 사용자가 캔버스에서 전환
- 노드 간 데이터(msg): **ExpandoObject** 기반 동적 객체(`Msg : DynamicObject`), Newtonsoft.Json으로 JSON 변환, Clone()으로 분기 시 데이터 격리
- Fan-out 실행 순서: 기본 순차 + 노드별 병렬 옵션(하이브리드)
- 순환 구조: 허용 + hop-count 기반 런타임 안전장치
- 병렬 처리: Task 기반 비동기 + 노드별 SemaphoreSlim 동시성 제한
- 변수(Context): Global/Flow/Node 3단계 IContextStore, 기본 메모리 + 파일/DB 플러그인 교체 가능
- 공유 서비스(TCP 서버 등): ISharedServiceNode + SharedResourceManager 참조 카운트 기반 싱글턴
- 프로세스 구조: **NodeSharp.Editor(설정/조작 화면)와 NodeSharp.Runner(실행 전용)를 완전히 별도 프로세스로 분리**하는 것을 기본안으로 확정 (단일 프로세스는 개발용 미리보기 옵션으로만 제공)
- 실시간 모니터링: Runner→Editor SignalR Hub로 노드 상태/흐름/디버그 이벤트 스트리밍 (Node-RED 디버그 사이드바·노드 status 동일 UX)
- Node-RED 기능 보강: Credential 암호화, 팔레트 자기서술(속성 편집 UI 자동생성), Catch/Status/Complete 노드, Subflow 상세, Link 노드/환경변수/Enable-Disable/버전관리
- 엔지니어링 보강: 백프레셔(Channel), 재시도/회로차단(Polly), Graceful Shutdown, 배포 전 Flow Linter, 노드 성능지표, 테스트 하네스, 플러그인 버전 가드, Undo/Redo
- lssLib 노드 모듈화: D:\lssLib 11개 모듈(Log/Messaging/Serialization/Net/Retry/Sequence/DB/Config/SignalR/Utils)을 `LssLibNodeAdapterBase` 공통 어댑터로 노드화, PropertySchema 기반 UI 설정 연동
- 코딩 컨벤션: 상세 XML 주석 + 다수 예제(`<example><code>`) — D:\lssLib 기존 코드 스타일을 그대로 승계, 4단계 구현 코드부터 전면 적용
- 계층형 구조 설정: 장비→PLC→디바이스맵→태그→스케일→알람 6단계 고정 트리(IIoT.Studio 패턴), Editor에 [구조 설정] 탭 별도 신설, Flow 캔버스와는 `TagRef` 속성 필드로 연동
- 2차 검토 보강: Editor↔Runner 토큰 인증, Function 노드 실행 격리(타임아웃+위험 API 경고), 알람 런타임(AlarmStateManager+Ack), 태그 Historian, TagRef 참조 무결성 검사, 프로젝트 번들(.nsproj), Runner Windows Service 자동재기동, 다세대 백업, 알림 채널 노드, i18n/캔버스 가상화, 다중 Runner는 향후 로드맵
- 3차 검토 보강: 배포 모드 세분화(Full/ModifiedFlows/ModifiedNodes/RestartFlows), 노드별 예외 격리, 설정 마이그레이션(lssLib.Config), Inject/Switch 노드 상세 설계, PLC Write 노드(범위검사+쓰기락), DeviceMapPoller 배치폴링+TagValueCache, 바이너리 payload 규칙, 감사 로그, Editor/Runner 프로토콜 버전 핸드셰이크, 구조 트리 포트 충돌 검사, UTC 타임스탬프 기준
- 4차 검토 보강(정합성 감사): grep 전수조사로 발견한 설계 내부 모순 4건 수정 — ① NodeContext 이중 선언/멤버 누락을 정식 통합판으로 정리(Structure/Shared/Scheduler/Env/Engine/EventBus 포함) ② Editor 전용 StructureTreeNode(ObservableCollection)를 헤드리스 Runner(DeviceMapPoller)가 직접 참조하던 계층 위반을 IStructureService/TagRuntimeInfo(순수 데이터)로 수정 ③ NodeConfig/FlowDefinition 생략 표기를 전체 필드 정식 선언으로 완성 ④ IScheduler 인터페이스+AsyncSchedulerAdapter 신설로 Scheduler API 암묵적 사용 해소
- 문서 구조 재편성(v1.6): 시간순으로 쌓이던 "1~4차 검토 보강" 탭을 해체해 관련 주제 탭(핵심 클래스/실행 흐름/모니터링·보안/계층형 구조 설정/기능 보강/엔지니어링 보강)에 흡수, 14개 탭 → 12개 탭으로 재구성. 각 회차가 무엇을 언제 발견했는지, 그리고 지금 어디로 이동했는지는 12번 탭 "검토 이력"에 인덱스로 보존
- 5차 검토 보강(v1.7): 재편성 이후 추가 grep 감사로 발견한 공백 6건 반영 — ① EventBus 구독 후 미해제로 인한 이벤트 핸들러 누수(실제 버그, TcpInNode·CatchNode 수정 + 6번 탭 이벤트 구독/해제 규칙 카드 신설) ② Editor↔Runner 전송 구간 암호화(TLS) 방침 ③ Runner 자체 헬스체크(/health) 엔드포인트 ④ Editor 캔버스 복사/붙여넣기·팔레트 검색 UX ⑤ 배포 패키지·설치/업데이트 설계 ⑥ 성능 목표치(SLA) 초기 수치
- 6차 검토 보강(v1.8): 공백 4건 반영 — ① 태그 Historian·감사로그 보존 기간(Retention) 정책(RetentionSweeper, 기본 30일/1년) ② MQTT 프로토콜 전용 시맨틱(MqttInNode/MqttOutNode — Topic 와일드카드·QoS·Retain·LWT, 범용 NetIoNode와 분리) ③ credentials.json 등 민감 파일 Git 저장소 제외(.gitignore) 규칙 명시 ④ 라이선스 정책(미정, lssLib 라이선스 확인 후 4단계 착수 전 확정) 추가

UI 목업도 통합 화면 + 시퀀스 에디터로 갱신
- 캔버스↔구조설정 데이터 연동 보강(v1.14): 카드 15가 "값이 흘러오는 방향"만 다루던 공백 발견 → ① 통합 저장/배포(`SaveAndDeployAsync` — 구조만 바뀌면 재배포 없이 `ReloadStructureOnlyAsync`로 가볍게 처리) ② `CommandHistory`를 캔버스·구조 트리가 공유(Ctrl+Z가 도메인 무관하게 최근 작업 되돌림) ③ `EditorSessionState`(Dirty 추적)+파일별 미저장 표시(●)+창 닫기 확인+동시편집 파일 락(device.json도 flows.json과 동일 규칙) 반영.
